Get started

Add it, sign in, switch off what you do not want

Three steps, no account of ours in between. The bot only ever holds what Discord gives it, and the dashboard runs on this deployment rather than on somebody else's service.

  1. 01

    Put it in the server

    {% if invite_url %} The full invite asks for Administrator, which is one permission bit and the reason no feature ever answers “Missing Permissions”. {% if invite_limited_url %} The least-privilege invite is the other half: only the permissions a command is known to need, each of them traceable to the call site that wants it. {% endif %} {% else %} This deployment has no invite link configured yet — set a Discord client id and restart it. {% endif %}

  2. 02

    Open the dashboard

    Run /help in your server and press the dashboard button. That mints a one-time link for the server you ran it in — it works once, expires quickly, and reaches no other server.

  3. 03

    Decide what runs

    {{ system_count }} systems, {{ command_count }} commands. Each system has one switch per server, and the switch is the only thing that decides what that server's members can type.

01 — Ways in

Three doors, and what each one reaches

A page must not offer a method this deployment does not have, so this list is read from the environment.

    {% if oauth_enabled %}
  • Discord sign-in Asks for your name and your server list, keeps only the servers where you hold Manage Server or Administrator and the bot is present, and re-checks that list on every request — so a server you were demoted from stops being reachable immediately. Sign in.
    • {% endif %}
  • One-time link The ⚡ Open Dashboard button on /help. Scoped to the server it was minted in, usable once, and it never becomes a lasting credential.
  • Operator passkey The deployment owner's own door, and the only one that reaches every server at once. It is off unless the host sets it, and the console behind it is a separate surface with its own unlock.

02 — What it holds

Where the data lives

  • One SQLite file On this deployment's own host. Settings, levels, the economy ledger, tickets, warnings and the scheduled queue all live in it — no third-party database.
  • Message content Not stored. The moderation log records the action, the member, the channel and the moment; it does not keep a second copy of what somebody typed.
  • Retention {% if retention_days %}Readings older than {{ retention_days }} days are dropped by the tracker's own windows.{% else %}Nothing is kept longer than the feature that needs it.{% endif %} The privacy policy is the same file the /privacy card reads.
