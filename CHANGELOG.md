# Changelog

## Unreleased
- **🔴 Two comparison bugs were burning the write budget on changes that never happened**: Discord returns `default_member_permissions` as a **string** (`"8"`) while discord.py sends the integer `8`, and it **strips the emoji variation selector** `U+FE0F` — so `/rps`'s `"✂️ Scissors"` is stored as `"✂ Scissors"` and `/leaderboard`'s `"🎙️ Voice Chat Time"` as `"🎙 Voice Chat Time"`. Both made those commands look permanently out of date, and because the sync re-sends whatever looks changed, **exactly those commands were re-uploaded on every boot** — forever. Verified against the live application, which reported eight gated commands plus `/rps`, `/leaderboard` and `/roulette` as changed while they were identical; the live scopes now report **`stale=0`**. `tests/test_command_sync.py` pins both payloads exactly as Discord returned them.
- **🔴 `/sync` was a second route to the wipe, and is now safe**: the slash command still called `tree.sync(guild=...)` and then `tree.sync()` — the destructive *bulk* overwrite that clears a scope's whole command list before rebuilding it — so an admin running `/sync` while the daily write limit was spent would have wiped the guild again, from inside Discord. It now goes through the same additive publisher as the boot sync (`bot.publish_commands`, reached through the bot instance because importing `bot.py` from a cog would re-execute the entry module), and reports what it published without claiming a removal that never happened. `tests/test_command_sync.py` parses the command and fails if a bulk sync or `copy_global_to` returns to it.
- **Commands are also published to Discord's global scope**: the guild lane can be closed for a whole day (`30034`) while the *global* scope has its own budget — verified live, where a guild write was refused but a global one succeeded. The boot sync now publishes missing/changed commands globally first, so every server the bot is in (and any it is invited to later) still shows them; read-compare-write means an unchanged tree costs nothing. `sync_commands` reports it under `"(global)"`, and a spent global budget is drained in the background like a guild's.
- **The background drain now has long enough to finish**: it gave up after 4 hours and passed the rest to "a restart will carry on", but nothing restarts the process on its own — so a guild that was tens of commands behind could be left part-full indefinitely. The budget is now 12 hours, which is long enough for it to actually converge at the rate the window refills.
- **🔴 Commands now register themselves — the tree had drifted to 71 of 93 and `/sync` was missing**: the bot never published its command tree on startup, and the only path that existed was the manual `/sync` slash command, which has to be registered before it can be used. The live guild was therefore stuck 22 commands behind — `/loan`, `/repay`, `/crash`, `/marry`, `/rizz` and `/sync` itself all existed in the code and simply weren't registered, so nothing anyone ran from inside Discord could bring them back. `bot.py` now syncs every guild on boot (per-guild, so a newly invited server self-heals too), and `force_sync.py` does the same from a shell without waiting for a redeploy.
- **The sync respects Discord's command-write budget**: Discord allows 200 command writes per day per guild and then answers error `30034`, after which *nothing* registers and it looks exactly like "the new command never appears". The tree is therefore compared before it is written (`utils/commands_sync.py`): a guild that already matches is left alone, and only genuinely new or changed commands cost a write. Because that budget refills a slot at a time, a guild with commands still pending is drained by a background loop that keeps publishing until it is complete (up to 4 hours), instead of needing another restart.
- **🔴 The sync can no longer delete commands**: Discord applies a *bulk* command sync destructively — it drops the guild's whole command list and then rebuilds it — so when the daily write budget ran out mid-request the deletes had already landed and the guild was left with **one** command instead of 74. Each command is now sent with its own upsert request, which can only add or replace, so a rejected request is harmless. `force_sync.py` defaults to that additive path as well; `--overwrite` re-enables the old, destructive bulk call explicitly.
- **The comparison ignores what Discord doesn't echo back**: discord.py sends `options: []`, `contexts: null`, `integration_types: null`, `required: false` and the deprecated `dm_permission` on every command, while Discord stores a default by *omitting the key*. A naive diff called every unchanged command "stale" — verified against the live guild, where 73 of 74 registered commands looked changed, which would have re-uploaded the whole tree on every boot and burned the daily budget on nothing. `tests/test_command_sync.py` pins the real payload shapes that were captured from Discord.
- **Meow Bank is a real bank now — your credit line grows with your level**: the loan system was one hardcoded rule (a flat 50,000 cap, 10% flat, a "7-day term" that nothing ever checked), so the leveling system had no effect on the economy at all. `/loan` now derives the credit line from your level (`utils/loans.py`: 5,000 base + 2,500 per level, capped at 250,000), shows your credit rating and what the next level unlocks, and lets you pick a plan — **Standard** (full line, 10%, 7 days), **Quick Cash** (5%, a third of the line, 3 days) or **Shark** (double the line, 30%, 2 days). `/repay` takes an `amount` and a `from_bank` switch, so a debt can be paid down in part and straight out of the bank.
- **A missed loan now has consequences**: the stored due date was written and then never read, so a "7-day term" meant nothing and a default was free. After a 6-hour grace period the outstanding balance takes a one-time 25% penalty (minimum 50), the loan is flagged overdue on the card, and new borrowing stays blocked until it is cleared. The penalty is applied inside the same transaction that reads the debt, guarded by a `late_fee_applied` flag, so two commands racing can only ever charge it once.
- **Borrowing and repaying are atomic**: `/loan` read "no active loan" on one connection and inserted on another, so two simultaneous calls both credited the wallet — and the loser of the race got an unhandled `IntegrityError` instead of a message; it now inserts and credits in one `BEGIN IMMEDIATE` transaction and the second caller is told they already have a loan. `/repay` debited with a plain `wallet = wallet - ?`, which *clamps at zero instead of refusing*, so two repayments could both "pay" coins that only existed once and the second cleared the loan for free; it now debits conditionally and checks the row count. `int(amount * 0.10)` also made any loan under 10 coins completely free — interest now has a floor of 1.
- **The `loans` table upgrades itself**: `/loan` gained `plan`, `status`, `taken_ts` and `late_fee_applied` columns. `CREATE TABLE IF NOT EXISTS` never alters an existing table, so a live database (and every cloud-restored copy of it) would have kept the old shape and the new commands would have failed on it; `utils/db.ensure_columns()` adds missing columns idempotently and old rows are backfilled as standard loans.
- **`/eco-admin add`, `remove` and `set` were registered but calling the wrong functions**: their handlers shared a name with the newer top-level `/addmoney`, `/removemoney` and `/setmoney` commands, and a duplicate definition in one class body silently re-binds the attribute — so the group's own implementations were unreachable dead code and the subcommands ran the top-level ones instead (which is why removing coins from a wallet ignored the admin/owner tiers). The top-level handlers are renamed with a `_cmd` suffix; a slash command's name comes from its decorator, so nothing user-facing changed and all four `/eco-admin` subcommands work again. `tests/test_static_health.py` had been failing on exactly this and is green again.
- **New funny commands**: `/beg` (spare change with a 2-minute cooldown, occasional humiliation, and a rare 100-coin whale), `/aura` (the universe rates someone, and the reading is final) and `/flex` (your net worth and, if the bank is involved, a reminder that flexing borrowed money is not a flex). `/flex` reads wallet, bank and live debt, so it is gated on both the fun and economy modules.
- **The two orphaned music tests skip instead of erroring**: `cogs/music.py` was removed but `tests/test_music*.py` stayed behind importing it, which made the suite red for reasons unrelated to any real change. They now skip with a message when the cog is absent and come straight back to life if it is restored.
- **Command budget**: with these additions the bot registers **92 top-level commands of Discord's 100 global limit** (`python -m unittest tests.test_commands` reports the tree; subcommands nest inside their parent and don't consume the budget). The 200 command-creates-per-day-per-guild ceiling is what `sync_background.py` paces, one command at a time with 429 backoff.
- **`/crash` no longer pays out after the card fails to update**: the round ran an interactive loop that edited its message every step, and on any edit failure it simply returned — with `view.ended` still false, so the **Cash Out button stayed live**. A player could then cash out at a multiplier the rocket may never have reached, while a player who did nothing lost the stake without ever getting to play. The round now ends, the buttons are cleared, and the stake is **refunded** with a "Launch Aborted" card.
- **`/crash` takes its stake atomically**: it debited with `update_wallet(-bet)`, which clamps at zero rather than refusing, so two all-in rounds that both read the same wallet could each start while only one was really paid for. It now uses `take_stake` and refuses a bet the wallet cannot cover.
- **`/sellanimals` can no longer be paid twice**: the rows were read on one connection and the coins credited on another, so two simultaneous sales of the same animals both computed a price from the same rows — the first deleted them, the second deleted nothing and was *still paid*. Read, delete and pay now happen in one `BEGIN IMMEDIATE` transaction, and the delete's row count is checked against what was read. The animals are also no longer deleted before the payment, so a failure can't cost the player both.
- **`/eco-admin remove` no longer claims coins it never removed**: it debited with `update_wallet(-amount)`, which clamps at zero, so removing 10,000 from a wallet holding 50 cheerfully reported "Removed **10,000**". It now debits exactly what is there (atomically, refusing if the wallet changed) and reports a partial removal when that is what happened.
- **The starboard's un-star path recovers from a deleted card**: it edited the card inside an `except: pass` and returned, so once a card was removed by hand or by a channel purge the row kept pointing at a dead message and the stored `stars_count` was never refreshed — the exact fault the add path had already been taught to self-heal. It now drops the stale row and re-posts, refreshes the count on a healthy card, and **keeps the row when the card itself cannot be deleted** (a missing Manage Messages permission), which used to make the next star post a duplicate beside the surviving card.
- **`/updatedb` no longer breaks other servers' logs**: it wrote the *home* server's channel IDs into whichever guild ran it, so in any other guild `log_channel_id` pointed at a channel that does not exist — and `_send_log` silently dropped every moderation action, while overwriting whatever the admins had configured. The seeded IDs are now applied only in the home guild; elsewhere it binds a local `#logs` / `#bot-cmd` if one exists, otherwise leaves the setting alone and says so.
- **Failures that used to vanish now say something**: a stale or foreign `log_channel_id` logs which case was not written, a forbidden log post is reported, and a ticket whose channel cannot be deleted tells the user instead of leaving the "deletes in 5 seconds" promise quietly broken.
- **The quote card shows the labels it was already computing**: `cat_display` and `mood_text` were built and then discarded, so a `/quote` card never said which category it came from or its mood. They are now in the footer (still plain text — no mentions).
- **Lint-level cleanup across the live tree**: six unused imports removed (`aiohttp`, `aiosqlite`, `asyncio`, `datetime`, `check_is_owner`, `dataclasses.field`), three bare `except:` clauses narrowed to the exceptions they actually expect (a bare clause also swallows `CancelledError`), two f-strings with no placeholder made plain, and several values that were computed and dropped are gone. `vc_xp`/`now` in the voice loop are *used* inside their transaction closure and were left alone.
- **A static-health test suite enforces all of it**: `tests/test_static_health.py` parses every live file and fails on undefined names, unused imports, bare `except:`, f-strings without placeholders, and duplicate definitions — using only the standard library, so there is nothing to install. `deleted_features/` is deliberately excluded, being an archive.
- **🔴 SECURITY — the dashboard no longer ships a default passkey.** `ADMIN_PASSKEY` fell back to a hardcoded string, so anyone who read this repository could sign in to any deployment that never set the variable — and `/api/set-module` accepted the same passkey with **no session and no CSRF token**, letting a stranger turn modules off in any guild. The value is now taken verbatim from the environment; when it is unset the passkey is empty, which disables passkey login and every passkey endpoint while the `/dashboard` one-time link keeps working. **If you were running with the old default, treat it as leaked and set `ADMIN_PASSKEY`.**
- **Casino bets can no longer pledge the same coins twice**: `/slots`, `/coinflip`, `/dice`, `/rps`, `/roulette` and `/gamble` read a balance and then applied a *net delta*, relying on `MAX(0, wallet + ?)`. That clamp is asymmetric — a loss could only take what you had, while a win paid in full — so several simultaneous invocations could wager the same coins repeatedly and keep every win. Every bet now goes through `settle_bet()`, which debits the stake conditionally and credits the payout inside one transaction; a bet that can't be backed is refused instead of being played for free. `/blackjack`, `/mines`, `/highlow` and `/tictactoe` now hold their stake the same way (`take_stake`), where a plain debit merely clamped at zero.
- **A timed-out blackjack hand no longer swallows the bet**: the 45-second turn timer ended the game without settling it, so a player who was dealt in and walked away silently lost their stake with no result. The timer now plays the dealer out and pays the hand exactly like Stand, and settling twice is impossible.
- **Tic-Tac-Toe stakes move together**: the challenge was accepted by debiting both players one after the other, so if the second debit failed the match started with only one player having paid into the pot. Both wagers are now taken in a single transaction, or neither is.
- **Deferred commands that fail now answer**: the error handler only replied when the initial response was unused, so any command that deferred and then raised left the user staring at "thinking…" forever. It now falls back to a followup message.
- **Moderation case numbers match their records**: the case number shown in `/warn`, `/ban` and the mod log was `COUNT(*) + 1`, so it drifted from the stored `case_id` as soon as a row was deleted ("Case #3" could be case_id 57) and two simultaneous cases could show the same number. It is now the inserted row's real id.
- **AutoMod can't be taken down by one un-deletable message**: `message.delete()` was unguarded, so a missing Manage Messages permission in one channel raised and aborted the listener before the notice (or the rest of automod) ran. The delete and the timeout are now guarded, and an unmutable spammer logs instead of breaking the loop.
- **Voice XP is written atomically**: the per-minute VC reward re-read the row on one connection and wrote it on another, so a message arriving in the same second could overwrite the minute's XP with a stale value (and a brand-new member was inserted twice). It now runs through the shared `run_atomic` helper.
- **The starboard recovers when its card is deleted**: the DB row kept pointing at a message that no longer existed, so every later star hit the same `NotFound`, the stored count was never refreshed, and the post could never be featured again. A deleted card now drops the stale row and re-posts, while a healthy card is still edited in place (verified: no duplicates).
- **The dashboard voice-debug endpoint no longer assumes music exists**: `/api/voice-debug` read `vc._player` directly, an attribute that only the archived music cog's `VoiceClient` subclass ever set. With music retired (or restored later) the lookup would raise and the endpoint would 500. It now reads the player defensively and reports `null` instead of crashing.
- **Commands in DMs explain themselves**: most commands read `interaction.guild.id` for the wallet, level row or module toggle, so invoking one in a DM raised `AttributeError` and answered "An unexpected error occurred". A central guard now replies "This command only works inside a server" (the handful of genuinely DM-safe commands are allow-listed in `utils/features.py`).
- **Two more slow memory leaks closed**: leveling's chat-cooldown map held one entry per (guild, member) forever, and the dashboard's login-attempt map held one deque per source address forever. Both are pruned once they grow past a sensible size.
- **`/uwu` can no longer be used to ping the server**: the command echoed member-supplied text back as plain message content, so `/uwu text:@everyone` (or a role/user mention) made the *bot* send the ping. The reply now sends with `AllowedMentions.none()`.
- **Admin confirmations no longer tag their target**: `/setlevel` and `/givexp` posted public messages containing `member.mention`, pinging the member — redundantly, since a real level-up is already announced by the card in the command channel. Both now show the display name.
- **`/announce` keeps pings, deliberately**: it is the one place a ping is the point, and its text is written by an admin holding Manage Server, so it opts in to `everyone`/`users`/`roles` explicitly. Every other card remains silent by default.
- **`/serverinfo` no longer reports "Server Owner: Unknown"**: `guild.owner` is `get_member(owner_id)`, which is `None` without the Members intent — the owner simply vanished from the card. The name is now resolved through the same fallback chain as the leaderboards.
- **`/levelroles` no longer claims every role has zero members**: `role.members` is only accurate when the member cache is real, so the count is now shown only when the Members intent is enabled instead of printing a confidently wrong number.
- **Leaderboards no longer ping anyone**: Components V2 promotes card text to a `TextDisplay` component, and — unlike the legacy embeds this bot used before — mentions inside a `TextDisplay` *do* notify. Adding a name to a ranking therefore tagged every member on it just because someone ran `/leaderboard`. `send_card`, `edit_card`, `send_panel` and `edit_to_panel` now suppress mentions by default (`AllowedMentions.none()`), and the one card that should reach someone — the level-up notice — opts in to pinging that member only, never the roles they unlocked. Intentionally-notifying sends (ticket pings, AutoMod notices, marriage proposals) were already plain `channel.send`/`response.send_message` calls and are unchanged.
- **Rich list and quote cards show real names instead of raw IDs**: `/richlist` resolved names with `guild.get_member()`, which is always `None` without the Members intent (this app has it disabled), so every row fell back to `User 1006948743314149426`. The same bug hit the custom-quote submitters in `/fun`. A new `display_name()` / `display_names()` pair in `utils/style.py` resolves names through the member cache, then a REST `fetch_member` (works without the intent), then the global user — and always returns plain text, never a mention, so a list can neither leak a snowflake nor ping.
- **Restore no longer silently discards the downloaded backup**: the restore path replaced `bot.db` but left the previous `bot.db-wal` / `bot.db-shm` in place, so SQLite replayed the *old, empty* write-ahead log over the freshly restored file. The download reported success while every row disappeared — a redeploy could come up completely empty. The stale log files are now removed before the swap, and a test reproduces the exact state a killed process leaves behind.
- **Backups now snapshot through SQLite, not a raw file read**: the database runs in WAL mode, so recently committed rows can still live in `bot.db-wal`. Copying the file could therefore upload a database missing the newest progress. Uploads now use SQLite's backup API, which produces a transactionally consistent snapshot including the write-ahead log, even while the bot is writing. (A row committed only into the WAL is covered by a test.)
- **Backups and the app now share one database path**: `utils/cloud_sync.py` kept its own `DB_PATH = "bot.db"` constant. Two copies of a path can drift, and a drifting backup path means the backup uploads whatever database happens to sit at *its* idea of the path. It now resolves `utils.db.DB_PATH` at call time, and the test-suite refuses to run against any file inside the project directory.
- **Uploads fail closed instead of overwriting good backups**: the backup job now refuses to write when the Gist holds encrypted backups but `BACKUP_ENCRYPTION_KEY` is missing, and when the local database has no level or economy rows while the Gist already holds a backup (the signature of a failed restore). Previously either case could replace real progress with an empty database. It also refuses to restore a payload that isn't a valid SQLite file.
- **End-to-end backup tests (17 of them)**: a redeploy simulation covering plaintext, encrypted, and the upgrade from one to the other, plus every failure mode — corrupt newest snapshot falling back to an older good one, missing key, missing credentials, non-SQLite payload, empty-database overwrite, snapshot pruning, and the exact `restore → db.setup()` order `bot.py` uses.
- **One feature registry instead of six copies**: `utils/features.py` is now the single description of every feature. The slash-command gates (`MODULE_COMMAND_MAP`), the dashboard cards, the module allow-list, the default on/off state, the help-menu structure and the cog list (`INITIAL_COGS`) are all derived from it. Previously adding or retiring a feature meant editing six places, and any drift produced exactly the reported symptoms — a green dashboard card next to a command that says the module is off, or a toggle that appears to do nothing. `bot.py`, `keep_alive.py`, `utils/db.py` and `cogs/help.py` no longer hold their own copies, and their startup validation logs any inconsistency. This also removed a stale `/ping` entry from the always-allowed command list — no such command exists.
- **A test suite (`tests/`)**, run with `python -m unittest discover -s tests -t .`. It pins the invariants that this codebase kept breaking: the closed-form level math against brute force at every level 0–500 and its inverse, the feature registry (including a real cog-load cross-check that fails if a slash command is added without being gated, or a gate names a command that does not exist), module-state persistence and concurrency, backup encryption/integrity, atomic money moves, and the Components V2 character budget. Standard library only, so there is nothing new to install.
- **Toggles have one owner now**: `utils/modules.py` holds the only module-state cache, reader and writer. The bot and the Flask dashboard previously kept *two* caches and *two* SQLite write paths, which is how they could disagree — a disabled module kept running, or a toggle silently reverted. `keep_alive.py` no longer touches SQLite for module state at all; it calls the same code the bot does. Retired module ids found in the database are ignored rather than resurrected on the dashboard.
- **Backups are encrypted, versioned and integrity-checked**: `utils/cloud_sync.py` now encrypts the database with PyNaCl SecretBox (XSalsa20-Poly1305) when `BACKUP_ENCRYPTION_KEY` is set, stores a SHA-256 of the plaintext inside the payload and verifies it before restoring (so a corrupted or tampered snapshot is refused rather than loaded), rotates timestamped snapshots keeping the newest `BACKUP_KEEP` (default 5) for point-in-time restore, and deletes the old plaintext copy the moment encryption is enabled. Without a key it still works exactly as before, but warns loudly on every upload. PyNaCl was already a dependency.
- **Every money move goes through one helper**: `utils/db.run_atomic()` replaces the nine hand-copied `BEGIN IMMEDIATE` blocks in `cogs/economy.py`. The helper takes a callback so callers keep their conditional logic (only crediting the receiver when the debit actually matched), and any exception rolls the whole transaction back. The balance operations now run in a worker thread instead of blocking the event loop.
- **One app-command error handler instead of two**: `bot.py` registered an error handler with `@bot.tree.error` *and* overwrote `bot.tree.on_error` in `on_ready`, so one of them was dead depending on timing. There is now a single handler, and an optional `ERROR_WEBHOOK_URL` forwards unhandled command errors somewhere visible instead of only printing them.
- **Level-up cards are confined to the command channel**: `handle_level_up` used to walk a five-step fallback (configured channel → hardcoded #bot-cmd → any channel whose *name* contained "cmd" → the server system channel → the channel the member was chatting in), which scattered level-up spam across the server. It now posts to the channel chosen with `/levelsettings`, else #bot-cmd, and if neither exists it posts nothing at all. The `bot_cmd_channel_id` setting that `/updatedb` wrote but nothing ever read is now honoured, so the target channel is configurable rather than hardcoded.
- **`/rob` stakes are now symmetric**: the take and the penalty come from the same roll, so it's no longer "risk a flat 100–300, win up to 50,000". A 2,000 🪙 attempt now costs a 200 🪙 fine if you're caught (10% of what you went for), the fine is capped at what you actually hold, and the card shows both the take and the risk. Tuning lives in `ROB_SUCCESS_CHANCE` / `ROB_FINE_RATIO` / `ROB_MIN_FINE` / `ROB_MAX_TAKE`.
- **Cooldowns on the free-money luck commands**: `/rob` (30 min), `/hunt` (10 min) and `/trivia` (3 min) previously had none, so they could be farmed indefinitely — `/trivia` paid 150–350 coins per correct answer with no limit at all. Bet-based casino games are left alone, since you risk your own coins there.
- **Humanised cooldown messages**: the global handler now reports "30m 0s" instead of "1800.00s".
- **Economy can no longer be duplicated**: `/pay`, `/deposit`, `/withdraw`, `/buy` and `/rob` read a balance, then wrote it back with no transaction, so two of them fired at once both passed the check — minting coins, driving the wallet/bank negative, or handing out two items for one payment. Each is now a `BEGIN IMMEDIATE` transaction with a conditional `WHERE wallet >= ?` guard and a row-count check.
- **Cooldowns can't be double-claimed**: `/daily`, `/weekly` and `/work` used the same read-then-write pattern, so two simultaneous claims paid out twice. They now use an optimistic single-statement claim that only fires if the stored timestamp is unchanged.
- **Starboard reacts to un-starring**: only `on_raw_reaction_add` existed, so a card's star count could only climb and a featured post could never come down. Added `on_raw_reaction_remove`, which re-syncs the count and retires the card (and its DB row) when it drops below the threshold.
- **AutoMod no longer leaks memory**: the per-user message log kept one entry per member forever; it now prunes quiet users and has a hard 5000-entry ceiling.
- **Leveling can no longer be inflated**: `utils/levels.py` now owns the XP/level math with a hard `MAX_LEVEL` ceiling, and `/setlevel` / `/givexp` are capped to it. Previously they accepted anything, which is how the server ended up with a Level 1351 rank-up card and a 2.4-billion-XP leaderboard entry. A one-time guarded repair re-derives every stored level from its XP and clamps out-of-range rows.
- **Leveling math is now O(1)**: the level lookup used to loop once per level (and `total_xp_for_level` summed the whole series in Python) on every message; both are now closed-form, so a high-level member no longer slows message handling.
- **Text XP / message counts no longer silently lose data**: message XP now uses a `BEGIN IMMEDIATE` transaction, so two messages arriving together can't both read the same old XP and drop one.
- **Leveling survives legacy NULL settings**: `get_guild_settings` coerced nullable columns, where `None >= 10` would previously raise and kill the whole reward path for that guild.
- **Privileged intents are now explicit and safe**: `ENABLE_MESSAGE_CONTENT_INTENT` / `ENABLE_MEMBERS_INTENT` (default off) let you opt in *after* enabling them in the Developer Portal. The app currently has neither enabled, so message text is invisible — that made AutoMod invite filtering a no-op and award XP at the baseline rate. Text XP now falls back to the standard rate instead of awarding nothing, starboard falls back to a readable description, and a clear log line explains how to enable the intents.
- **Archived six fragile features**: Music & Radio, TempVoice (Join-to-Create), Welcome/Goodbye, Color Studio & Roles, Giveaway System and Reaction Roles are removed from the running bot. Their code moved to `deleted_features/` (kept intact, never imported) along with the music-only `utils/spotify.py` + `utils/card.py` and the `yt-dlp`/`imageio-ffmpeg` dependencies. Dashboard cards, help categories, command-map entries and docs were cleaned up. Their SQLite tables were intentionally left in place so no stored data is dropped.
- **Module toggles actually stick**: The web dashboard now writes the change to the database *before* updating memory and reports a real failure instead of silently claiming success, and every toggle triggers an immediate cloud backup so a restart can't restore an older snapshot and revert it.
- **Fixed modules running while disabled, or not running while enabled**: SQLite now runs in WAL mode with a 15s busy timeout, ending the lock contention between the web thread and the bot thread. Previously a failed read made `is_module_enabled` fall back to `True` (so a disabled module kept running) and a failed write silently dropped the toggle. Reads and writes now fail loudly and retry instead of silently guessing.
- **Shared module defaults**: `DEFAULT_DISABLED_MODULES` in `utils/db.py` is the single source of truth for default state, used by both the bot and the dashboard so they can never disagree. **Giveaway, Color Studio & Roles, and TempVoice now default to OFF** (alongside Welcome). A one-time migration applies this to guilds that had an old saved value.
- **Disabled means disabled**: the giveaway background loop and entry button, and the color palette dropdown, now honour their module toggle (view callbacks previously bypassed the cog checks).
- **Components V2 message system**: Added a full Components V2 design system to `utils/style.py` — semantic cards (`success`/`error`/`info`/`warn`), a rich `card()` builder with fields, thumbnail, media gallery and footer, `progress_bar()` for XP/cooldowns, and an `embed_to_layout()` converter that upgrades any legacy embed into a container card. Text is clamped to Discord's 4000-character / 40-component V2 limits, and every helper falls back to the original embed if conversion or sending fails, so no command can break.
